# Phases 4, 5, 6: UI Kit, Onboarding and Commuter Screens Implementation Plan

> **For agentic workers:** Tasks run as parallel subagents, each in its own worktree under `D:/Files/Coding/Github Repo/worktrees/paratrack/`, branched from `phase-4-6`, which is branched from `main`. The controller reviews every task in the main session and merges it into `phase-4-6`. Tasks in a wave start only after the previous wave is merged.

**Goal:** The shared UI kit built from the Figma Components page, onboarding plus phone login (Figma 01-05, 24, 25), and the commuter screens (Figma 06-14, 20-23), running on web (Next.js) and Android (Expo) from one set of screens.

**Architecture:** `@repo/ui` is consumed from source and holds tokens, components, screens, data hooks and the platform shims (`*.web.ts(x)` / `*.native.ts(x)`). `apps/web` and `apps/native` contain only route files, each a one-line re-export of a shared screen, plus app shells. Data comes from Supabase through `@supabase/supabase-js` and `@repo/core`.

**Tech Stack:** NativeWind 4.2.7 + Tailwind 3.4, React Native Reusables (hand-adapted, cva + `cn`), Reanimated 4.2.1 + Worklets 0.7.4, react-native-svg 15.15.3, phosphor-react-native, Inter, Next.js 16, Expo SDK 55 + expo-router, Supabase JS, Google Maps (`@vis.gl/react-google-maps` on web, `react-native-maps` on Android), Vitest, Playwright.

**Spec:** `plan.md` (Decisions, Tech stack, How the app works, Motion, Phase 1 results) and the Figma file `46EIhMGyMDUB4712Nqp1au` (page "Screens (redesign)" frames 01-28, page "Components (redesign)").

## Global Constraints

- **Login is phone before Home** (user decision 2026-10-05). Commuters go 01 Welcome → 02 Location → 03 Mobile number → 04 Verify code → 06 Home. Drivers go 01 → "I drive a route" → 03 → 04 → 05 Verify vehicle. Anonymous sign-in is not used by the app.
- **Versions:** pin exactly Reanimated 4.2.1, Worklets 0.7.4, react-native-svg 15.15.3, gesture-handler ~2.30.0 (Expo SDK 55 values). NativeWind 4.2.7 with Tailwind 3.4.x, never Tailwind 4. `apps/web` lists `react-native` 0.83.10. React stays a single 19.2.0. Native packages go in with `npx expo install` inside `apps/native`.
- **Styling:** colors, spacing, radii, type and shadows come only from the shared Tailwind preset built from the Figma variables. No raw hex in components or screens.
- **Figma fidelity:** before building any component or screen, load the Figma design-to-code guidance (`/figma-design-to-code` skill if listed, otherwise read MCP resource `skill://figma/figma-design-to-code/SKILL.md`), then call `get_design_context` for that exact node. Match the layout, copy and states. Copy changes from `plan.md` win: "Student fare" instead of "Student ID verified", and a "Jeep" filter tab added to All / Shuttle / E-jeep / Bus.
- **Accessibility:** touch targets at least 44x44, every icon-only control gets `accessibilityLabel`, text contrast follows Figma tokens, and every animation has a reduced-motion branch (`useReducedMotion` from Reanimated).
- **Motion** (plan.md "Motion"): press feedback on buttons, sheet height transitions, list rows entering and exiting, values ticking. Use the presets from Task 2's `motion.ts`.
- **Data:** select explicit `vehicles` columns (`operator_id` is withheld). The commuter's location never leaves the device.
- Commit messages: sentence-case subject, short body, `Claude-Session: https://claude.ai/code/session_018R2boTZgvdq868jZ7PnZPd`, no co-author line. Use `git commit -F <file>`.
- Every task ends with CI green on its branch (`gh run watch`).

## Shared conventions

`packages/ui/src/` layout:
```
theme/      tailwind preset (tokens), fonts helper
lib/        cn.ts, nav.web.ts / nav.native.ts, supabase.web.ts / supabase.native.ts, motion.ts
components/ one file per Figma component set (Button.tsx, TextField.tsx, ...)
data/       React hooks over Supabase + @repo/core (useSession, useRoutes, useVehicles, ...)
screens/    one folder per flow: onboarding/, commuter/, states/ (re-exported in index.ts)
```

## Review Focus

1. **A shared screen that renders on web but crashes on Android (or the reverse).** Each screen task checks both: `npm run build` (web) and `npx expo export -p android` (native bundle) must pass.
2. **Styles silently missing.** A NativeWind class that does nothing on one platform: animated components need `cssInterop`, and Tailwind `content` must cover `packages/ui/src`. Screen tasks screenshot web pages with Playwright and compare them with the Figma screenshot.
3. **Login edge cases.** Paste with spaces, `09` vs `+63` input, the resend timer, wrong code, expired session. Covered by Task 5's e2e tests.
4. **Live data gaps.** A vehicle going offline mid-view, no vehicles at all, a network drop. Covered by Task 6/7 states and e2e tests with `context.setOffline`.
5. **Small targets.** Map markers and stops in Figma are 14-36 pt. The hit area must be at least 44 pt even when the visual is smaller.

### Task 4: Data layer (branch `p6-data`, parallel with Task 1)

**Files:** `packages/ui/src/lib/supabase.web.ts` / `.native.ts`, `packages/ui/src/data/*`, tests.

1. Supabase client per platform. Web: `createClient(NEXT_PUBLIC_SUPABASE_URL, NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY)` with localStorage. Native: `EXPO_PUBLIC_*` with AsyncStorage (`npx expo install @react-native-async-storage/async-storage`). Both are typed with `Database` from `@repo/core`. Export `supabase` as a singleton.
2. Hooks (plain React state + effects, no new state library):
   - `useSession()`: session, user, loading. Plus `signInWithPhone(e164)`, `verifyCode(e164, code)` and `signOut()`.
   - `useProfile()`: read and update own profile.
   - `useRoutes()`, `useStops()` and `useRouteStops(routeId)`: loaded once and cached in module memory.
   - `useLiveVehicles()`: vehicles (explicit columns) joined with `vehicle_live`, subscribed to Realtime `postgres_changes` on `vehicle_live`. Exposes `{ vehicles, status: 'connecting' | 'live' | 'offline', lastUpdate }`. Realtime channel status plus `navigator.onLine` / NetInfo decide `offline`.
   - `useNearby(position)`: for each route, the nearest stop to the position (`haversineM`), then the ETA of each online vehicle to that stop (`etaSeconds`), sorted by ETA. Returns rows `{ vehicle, route, stop, etaSec, walkMin, seat: seatStatus(...) }`.
   - `useTrips()`: own active trips. `startTrip({vehicleId, boardStopId, alightStopId})`, `setOnboard(tripId)`, `endTrip(tripId)`, `setTripAlerts(...)`.
   - `useNotifications()`: own notifications, Realtime inserts, `markAllRead()`, `unreadCount`.
   - `useFare(routeId, fromStopId, toStopId, fareType)`: distance from stop offsets via `ahead`, then the `fare()` breakdown.
3. Pure helpers stay in `@repo/core` if they are logic (for example `nearestStop`, `walkMinutes` at 80 m per minute). Add them there with tests.
4. Tests: Vitest for every new `@repo/core` helper. One integration test against dev (CI: local stack with the Tarlac seed) that `useLiveVehicles`'s underlying query returns all 8 seeded vehicles with explicit columns. Test the query function, not the hook render.

**Verification:** `npm test`, both typechecks, CI green.
